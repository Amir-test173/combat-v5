# World Dominion v0.7

نسخة تطويرية قابلة للعب مبنية بـ Flutter، مع سيرفر Node.js/WebSocket authoritative للـMultiplayer.

## الجديد في v0.7

- كل دولة كمبيوتر أصبحت كيان AI مستقلًا (`AI:USA`، `AI:TUR`...) ويمكن لدول الكمبيوتر أن تتوسع وتحارب بدل أن تكون كتلة واحدة ساكنة.
- استمرار التوسع عبر الأراضي المحتلة والجبهات المتصلة كما في v0.6.
- جيوش ميدانية: مشاة، دبابات، مدفعية، دفاع جوي، طائرات، مروحيات، مسيّرات واستطلاع.
- طبقة مدن ومنشآت استراتيجية داخل كل دولة: عاصمة، مجمع صناعي، محطة طاقة، مركز إمداد، قاعدة جوية، وموانئ للدول الساحلية.
- سلامة لكل منشأة من 0 إلى 100%. يمكن تنفيذ غارة دقيقة على منشأة محددة أو إصلاحها أو بناء منشأة إضافية.
- أضرار المصانع تقلل إنتاج الحديد والمال، أضرار محطات الطاقة تقلل إنتاج الكهرباء، وأضرار مراكز الإمداد تقلل استعادة الإمداد.
- احتلال دولة متضررة يعني أنك ترث منشآتها بحالتها، ولذلك تدمير كل شيء قبل الاحتلال قد يضر المنتصر أيضًا.
- مقاومة شعبية للاحتلال. النقص وقطع الإمداد يرفعان المقاومة وقد يسببان انتفاضة واستقلال الإقليم.
- الاحتلال يضيف كلفة إدارية من الغذاء والمال على سلطة الاحتلال، خصوصًا في الدول ذات السكان المرتفعين.
- إذا سقطت العاصمة وبقيت لك أراضٍ، ينتقل مركز القيادة/الإمداد مؤقتًا إلى إقليم ما زلت تسيطر عليه بدل توقف اللاعب بالكامل.
- حفظ محلي للمباراة الفردية عبر SharedPreferences، مع استعادة من الشاشة الأولى وحفظ تلقائي عند إنهاء الدور.
- استعادة هوية لاعب الـMultiplayer بعد إعادة الاتصال دون إعادة اختيار الدولة أو إعادة احتلالها مجانًا.
- التحالف بين لاعبين حقيقيين أصبح طلبًا يحتاج قبول الطرف الآخر، وإنهاء التحالف إجراء منفصل.
- التحالف مرتبط بهوية الحكومة ويشمل الأراضي التي احتلتها؛ لا يمكن مهاجمة إقليم تابع لحليف للتحايل على المعاهدة.
- تقليل البيانات الداخلية المرسلة إلى Lobby: اللاعبون الآخرون يرون الاسم والدولة وحالة الاتصال فقط.
- خريطة بطبقة مناطق سيطرة استراتيجية مرئية ومنشآت على الخريطة. **هذه الخلايا ليست حدود GIS حقيقية بعد**؛ هي طبقة لعب تكتيكية مؤقتة إلى حين دمج بيانات الحدود الجغرافية الفعلية.

## تشغيل Flutter

```bash
flutter pub get
flutter analyze
flutter run
```

لبناء APK:

```bash
flutter build apk --release
```

الملف الناتج عادة:

```text
build/app/outputs/flutter-apk/app-release.apk
```

## بناء APK بدون Flutter على جهازك

المشروع يحتوي:

```text
.github/workflows/ci.yml
```

ارفع **محتويات المشروع** إلى GitHub. Workflow باسم `Build World Dominion` يقوم بـ:

1. تثبيت Flutter Stable.
2. إكمال ملفات Android بواسطة `flutter create . --platforms=android`.
3. `flutter pub get`.
4. `flutter analyze`.
5. `flutter build apk --release`.
6. رفع APK كـ Artifact باسم `world-dominion-v0.7-apk`.

## Multiplayer

السيرفر داخل مجلد `server/`. شغله محليًا:

```bash
cd server
npm install
npm start
```

اختبار:

```text
http://localhost:8080/health
```

اللعب عبر الإنترنت يحتاج رابطًا عامًا `wss://...`. راجع `SERVER_SETUP_AR.md`.

## الحفظ

- اللعب المحلي: SharedPreferences على الهاتف.
- السيرفر بدون `DATABASE_URL`: JSON داخل `server/data/`.
- السيرفر مع `DATABASE_URL`: PostgreSQL.

## ملاحظة عن التوازن

الأرقام الحالية متعمدة لتجربة الأنظمة وليست توازنًا نهائيًا. قبل إصدار عام نحتاج Telemetry واختبارات لعب لضبط تكاليف الجيش والطاقة والاستهلاك واحتمال الانتفاضات.
